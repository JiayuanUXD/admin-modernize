# adapters：栈相关的知识放这里

通用 skill 不依赖具体技术栈。栈相关的东西——某个 UI 库的 DOM 类名、它的标准件、构建工具里怎么挂 mock——放在 `adapters/<栈>/`，这样通用部分保持通用。

## 一个 adapter 可以提供

| 文件 | 内容 |
|---|---|
| `ratchet.config.json` | 该栈的规则包（`admin-guardrails` 的 ratchet 格式），覆盖这个 UI 库下反复出现的错误写法 |
| 标准件清单 | 共享的组件、样式、工具，及各自的耦合点和待办 |
| `README.md` | 来源（哪个参考实现、哪个版本）、规则的验证方式、没有移植的部分、版本敏感点 |

## 新建一个 adapter

1. 用 `admin-recon` 摸底，看这个栈上最集中的违规信号。
2. 列出 AI 在这个栈上反复犯的 5 个错（来自基准评测或评审记录），每个对应一条规则：有明确的替代写法，才值得做成规则。
3. 用 `map-tokens.mjs` 把硬编码值映射到该栈**已有**的 token，产出迁移清单。已有 token 就不新建一套；没有就先定（D3），再写规则。
4. 写规则包，用 `ratchet.mjs --report` 在一个已知的旧快照上跑，数字要和肉眼或既有 lint 能对上。
5. 整理标准件清单，标明耦合点：依赖项目私有模块的部分要先解耦再共享。
6. 记下版本敏感点（哪个版本的 DOM 类名、哪个补丁依赖哪个版本）。
