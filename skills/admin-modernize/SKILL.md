# admin-modernize：让老后台适配 AI 生成原型并对接后端

## 目标

两件事：**AI 生成的页面一次就对**；**原型接真实后端不返工**。不是把存量全改漂亮，名字里的 modernize 不是重写。

做法是在三层上投入，存量统一排在它们之后：

| 层 | 要达到 | skill |
|---|---|---|
| 约束面 | AI 照着做就对：少量标准件、样板页、机器能查的规则 | `admin-guardrails` |
| 反馈环 | AI 能看见自己做的结果：离线能跑、有数据、能截图 | `admin-preview-loop` |
| 对接面 | 原型能接上后端：数据层统一、契约先行、mock 与真实可切换 | `admin-api-contract` |
| 存量 | 老页面按价值逐步迁到新标准 | `admin-legacy-migration` |

原则：**先窄后宽、先新后旧、先契约后像素。**

## 技术栈

不依赖具体栈。插件根目录（本 skill 目录往上两级）的 `adapters/<栈>/` 放栈相关的规则包和标准件清单：有对应的就用，没有就用通用做法，做完后把栈相关部分整理成新的 adapter（见 `adapters/README.md`）。

## 阶段与门禁

时间是量级，按团队规模和存量大小调；顺序和过关标准不调。

| 阶段 | 量级 | 做什么 | 用什么 | 过关标准 |
|---|---|---|---|---|
| 0 摸底 | 2–3 天 | 量化现状，定成功指标，选试点 | **REQUIRED SUB-SKILL:** `admin-recon`；决策 D1、D2 | 指标和试点由用户确认 |
| 1 细切片 | 1–2 周 | 试点页从 AI 生成、离线预览、接真实后端一路做到上线；顺手做出最小约束面 | 三个能力 skill 的「最小版」 | 试点上线；标准 v1 冻结（D3） |
| 2 变设施 | 2–3 周 | 把切片里的手工部分做成设施；用基准需求评测，按返工原因改设施 | 三个能力 skill 的「完整版」；`references/metrics-and-eval.md` | 基准需求的指标达到 D1 的目标 |
| 3 持续 | 长期 | 新页面只走新路径；存量碰到就改、按价值批量迁 | `admin-legacy-migration` | 基线逐月下降，新页面零新增违规 |

阶段 1 必须接真实后端（测试环境即可），试点必须是真实要做的需求。否则验证的只是页面好不好看，不是能不能接上。

拓扑先判：`admin-recon --topology` 判定前后端是否同仓。**同仓时阶段 1 之前先走 `admin-repo-split`**（契约冻结 → 逻辑拆 → 物理拆）。拆仓不替代分支保护和目录白名单，见该 skill 的红线。

## 已落地的试点

当前真实切片是叮咚买菜 · 小红书体验雷达的洞察池（列表 + 抽屉，6 个接口），记录在插件根目录 `docs/pilots/dingdong-ux-radar-insights/`。D4 在这一例上覆盖了默认：没有 OpenAPI，但后端实现已经成熟，所以用 actual IR 走后端先行，不另起一份原型契约。

这次只跑通契约流水线（desired → gap → disposition → 骨架），并把踩坑写回了 `admin-api-contract`。没有改雷达页面，没有离线预览，没有接到测试环境。D1 笔记在该目录的 `d1-notes.md`。阶段 0→1 还没全跑通。

## 决策点（逐项问用户，不替用户选）

除 D4 外逐项问，不替用户选。D4 有默认，只在仓库里已经有成熟 OpenAPI 时问一次。

- **D1 成功指标与试点**：每页人工返工时长、首次检查通过率、接后端耗时、对接时发现的契约不一致数，各取现值和目标值；试点是哪个真实需求。
- **D2 谁生成原型、怎么交接**：产品、设计还是前端？在哪个环境（沙盒路由、预览分支）？谁评审契约、谁把原型晋升进生产？
- **D3 标准 v1 的范围**：先定代价高的（token、页面骨架、数据层约定、权限点的表达方式），可逆的后定。v1 在试点后冻结，之后的变更走评审。
- **D4 契约方向**：仓库里没有既有 OpenAPI / proto 时，默认 **原型先行**——原型侧契约文件是唯一来源，后端评审这份文件，不评审 UI。已有成熟 OpenAPI 时走 **后端先行**（由 OpenAPI / proto 生成类型与 mock）；这时只问一次，确认沿用该来源，不反复问。
- **D5 存量范围**：按访问量、改动频率、违规密度排优先级；哪些长尾不动；不同栈的页面是否路由级替换。

用户说「别问我问题」时，不停工，也不替用户决定：先做不需要决定的只读工作（摸底），再把决策点写成「建议默认值，请一句话确认」的清单，在那个节点停下。没有既有 OpenAPI / proto 时，D4 用默认，不要放进这份清单。

## 红线

| 念头 | 现实 |
|---|---|
| 先把存量全统一，再让 AI 生成 | 几周后才发现数据层才是返工大头。先走通一条切片 |
| 标准边迁边定 | 返工的来源。D3 没确认，不进阶段 2 |
| 用文字规则约束 AI | 文字会被「协商」掉。能写成 lint、类型、样板页的，不要只写文档 |
| 原型先做成独立 HTML，到时再转 | 转换等于重写。原型从一开始就在真实栈和标准件里做 |
| mock 手写几百个接口 | 手写的必然漂移。由契约生成 |
| 页面与契约双源手写维护 | 必然漂移。契约唯一来源，另一侧生成 |
| 先统一视觉，数据层以后再说 | 对接返工的大头在数据层 |
| 代码看着对，不用截图 | 视觉只能靠截图验证 |

## 完成判据

试点页上线且指标达标；检查命令在 CI 里强制；新页面由 AI 按仓库里的 `new-page` skill 生成，首次通过检查，接后端没有字段返工；存量基线逐月下降。
