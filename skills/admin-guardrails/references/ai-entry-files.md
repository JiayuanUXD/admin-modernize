# AI 入口文件与 new-page skill

## 入口文件（AGENTS.md / CLAUDE.md）

要短（目标 80 行以内），放地图和命令，不放规则正文。规则在 lint、类型、样板页里，这里只指路。

按优先级排的段落：

1. **项目与技术栈**：一句话，加对版本敏感的点（UI 库版本、构建工具）。
2. **命令**：启动离线预览、截图、检查（一条命令）、类型检查。
3. **页面从哪里来**：样板页清单，每个一句话说明它示范什么。写明「只参考这些，其余存量页面带历史写法」。
4. **标准件表**：要做什么 → 用哪个（路径）。
5. **禁止清单**：与检查规则一一对应，写规则 id。写明「确需例外加 `lint-allow: <标签> 原因`」。
6. **数据层与契约**：接口类型从哪个文件引入；页面里不拼 URL、不改参数名、不做枚举映射；契约变更的流程。
7. **完成定义**：检查命令通过、截图命令无报错、契约与 mock 对齐、交付说明已写。
8. **拿不准时**：业务字段不要编造，列出疑问问用户。

Claude、Codex 等多个工具并存时，正文只写一份，另一份文件指向它，避免两份漂移。

## new-page skill

放在目标仓库里（如 `.claude/skills/new-page/SKILL.md`）。流程固定，路径、样板页、命令换成该仓库的：

1. 读入口文件和最接近的样板页。
2. 确认需求：页面名与所属菜单、搜索条件、列、操作、状态枚举。缺业务信息先问，不编造。
3. 先写或更新契约（接口类型），字段加中文注释。与已知后端约定有出入的地方标出。
4. 复制最接近的样板，只改需要的部分，不新造布局。
5. mock：由契约生成，再补边界数据（空、超长文本、负数、0、大额、全部枚举）。
6. 起离线预览，逐个状态过一遍，对每个状态截图。
7. 跑检查命令，全部通过。
8. 写交付说明。

## 交付说明

AI 每次生成页面后输出，供人和后端评审：

- 新增、修改的文件，页面访问路径；
- 用到的接口，及契约所在位置；
- 按假设写的点（需要产品或后端确认）；
- 没有验证的状态或页面；
- mock 所在位置；
- 已知问题。
